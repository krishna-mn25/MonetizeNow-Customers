API field reference

Field-level reference for MonetizeNow API responses, webhook payloads, and write constraints. Covers every field on GET endpoints and create/update request bodies with types, length limits, and required/optional status.

How to read this

Each object has two sections: Response fields (what you get back from GET endpoints and webhooks) and Write constraints (what you can send on create/update, with length limits and required fields).

String Integer / Long BigDecimal Boolean Enum Date / Instant Object / List
  • required always present with a value. nullable may be null.
  • Nulls are always serialized. A nullable field appears as "field": null in JSON — the key is always present even when empty.
  • Max length shows the enforced limit on that field. Most string fields have no declared length limit. Where limits exist, they are noted.
  • Every response also includes 4 audit fields: createdBy (String), createDate (Instant), lastModifiedBy (String), modifyDate (Instant) — all nullable.

Cross-cutting rules

Patterns that hold across every object.

Response patterns

  • IDs are strings. All ID fields (accountId, invoiceId, quoteId, etc.) serialize as plain strings like "acct_oKEMgy...".
  • Relationships surface as IDs or nested objects (sometimes both, e.g. BillGroup has both accountId and account).
  • Enums serialize by name as string values ("ACTIVE", "USD"), never as numeric ordinals.
  • Monetary amounts are BigDecimal — no case of a monetary value being serialized as a String.

Write patterns

  • Create/update endpoints validate field types, required fields, and length limits. Invalid input returns 400 with error details.
  • Patch endpoints (e.g. POST .../quotes/{id}/update) use a different model: absent field = leave unchanged, explicit null = clear (where allowed), value = set. Type errors return 400 INVALID_PROPERTIES.
  • Custom fields are validated server-side against your tenant’s field definitions (type + 255-char text cap + dropdown allowed-values).
