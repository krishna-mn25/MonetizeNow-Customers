"First 2-3 Months Free" Entrance Discount›
Discounts #1 Priority Ready to Build
KKrishna · blueprint setupLLeidy · sandbox sign-off
What You're Running Into
Reps are offering 2-3 months free as an intro incentive, but there's no obvious way to set that up in MonetizeNow. So they're building quotes manually in Google Sheets and emailing PDFs. That means Salesforce data is incomplete, auditing is manual, and Casey can't see accurate pipeline numbers.
How We Solve It
MonetizeNow has a feature called Schedule Changes that lets you set different pricing for different periods within the same contract. We use this to build a "first 3 months free" structure with the real product (not a separate promo SKU):
  1. Add the actual subscription product to the quote (e.g., Endor Package Firewall). Not a promo version, the real one.
  2. Apply a 100% discount on that line item for the first period.
  3. Add a Schedule Change at month 4 (or whenever the free period ends). On this segment, set the discount to 0%. Full price kicks in automatically.
  4. Result: months 1-3 bill at $0, month 4+ bills at full price. One line item, one product, clean billing schedule.
Schedule changes can be set at any date in the contract, not just annual boundaries. So "3 months free" or "2 months free" or "45 days free" all work.
We'll Package This as a Blueprint
To make this repeatable for reps, we'll save this structure as a Quote Blueprint called "New Deal — 3 Months Free." When a rep creates a new quote, they select this blueprint and the entire ramp structure is pre-built. They just adjust the customer, quantities, and dates. Blueprints preserve the full schedule change structure, so nothing needs to be re-added manually.
We'll also create a "Renewal — Full Price" blueprint with zero discounts and no ramps, so renewal quotes start clean.
Renewal Behavior
For contracts with promotional ramps, we'll set the renewal type to Manual Renewal. That means when renewal time comes, Leidy or the rep creates the renewal quote using the "Full Price" blueprint. No promotional pricing carries forward by accident.
Sandbox first. We'll build both blueprints in sandbox, run a full lifecycle test (quote → process → billing run → renewal generation), and walk through it together before deploying to production. Krishna will have sandbox ready for review by Thursday.
What About ARR?
During the free months, ARR will show $0 for those periods. MonetizeNow calculates ARR from the billing amount in effect. If Casey needs a report showing the full committed contract value regardless of the promo, we can build a custom report that annualizes total contract value (TCV). We'll discuss this in the Casey meeting.

Proration Discrepancy on Co-Term Quotes (OpenAI $2K Issue)›
Pricing Sandbox Test Needed
KKrishna · test + recommendLLeidy / Casey · decide
What You're Running Into
On the OpenAI quote, 2,600 seats × $310 should equal $806,000. MonetizeNow calculated $804,000 because it prorates to the exact day. A 7-month-5-day period doesn't divide to a round number, so there's a ~$2K difference from what your customer expected (simple seats × unit price).
The Option
MonetizeNow has a product-level setting that turns off day-level proration entirely. When enabled, the system charges the full period amount regardless of partial-period math. 2,600 × $310 = $806,000 exactly.
  1. Go to Product Catalog → select the product
  2. Find Proration Policy
  3. Change from "Prorated" to "Non-Prorated"
This is a product-level setting, not per-quote. It applies to every quote using that product. If some deals need exact day-level proration and others need simple multiplication, this single toggle won't cover both. We should discuss which products to apply this to and test in sandbox with an amendment scenario (adding seats mid-term) to make sure the behavior matches what your team expects.

Pricing Guardrails — Reps Can Mark Up, Markdowns Need Approval›
Discounts Rules Ready to Configure
KKrishna · build ruleLLeidy · approve logic
What You're Looking For
Reps need the ability to adjust unit prices upward (anchoring strategy), but you don't want them able to drop below list price without RevOps approval. Right now only admins can make these changes, which makes you the bottleneck.
Two-Step Setup
Step 1: Open up pricing permissions. In Quote Settings → Account Specific Rates, grant your sales reps the ability to adjust prices on quotes.
Step 2: Add the guardrail. We'll create an Approval Rule that triggers whenever a rep sets a price below list. The way MonetizeNow tracks this: any price below list shows up as a positive discount percentage. So the rule fires when discount percentage is greater than 0% on an account-specific rate. Markups (above list) show as zero discount and sail through without approval.
For Leidy: You (or whoever you designate) will get an approval notification only when a rep tries to go below list price. Everything at or above list just works. This removes you as the bottleneck for standard pricing while keeping you in the loop for exceptions.
Next Step
Krishna will build this rule in sandbox. We'll test it together with a few scenarios (markup, markdown, exact list price) to make sure it fires correctly before enabling in production.

Primary Quote Flag — How It Works (for Your Reps)›
Lifecycle Ready to Share
What Was Confusing
Reps noticed the "primary" flag on quotes seemed to change on its own. Sometimes a cancelled quote was still marked primary, or a new draft unexpectedly became primary.
The Rules (Share with Reps)
A quote becomes primary when:
It's the first quote linked to an opportunity. Or it's accepted/processed (and at this point all other non-finalized quotes on that opportunity automatically cancel with "Suppressed by Processed Quote"). Or a rep manually sets it using the "Set as Primary" button on the quote.
A quote stops being primary when:
It's deleted or cancelled. MonetizeNow auto-picks a replacement (highest stage quote first, then most recently created). If no quotes remain, the primary field goes blank. Or another quote is set as primary manually.
The takeaway for reps: Creating multiple drafts is fine. They all clean up automatically when one gets processed. If your primary looks wrong, just click "Set as Primary" on the correct quote. And only process the quote you actually want to close, because processing cancels all the others.
Quote Expiration and Recovery Process›
Lifecycle Ready to Share
LLeidy · weekly check
How Expiration Works
MonetizeNow auto-expires quotes 30 days after creation (configurable). After expiration, there's a 7-day grace period to reactivate. After that, the quote auto-cancels permanently.
Preventing Expirations (Going Forward)
The "MonetizeNow View for RevOps" dashboard is already in your tenant under Reporting. It shows each rep's quotes, their status, and expiration dates. If a rep sees their quote is expiring soon, they can extend the expiration date directly from the quote header (15/30/60/90 days).
Recommended weekly check: Every Monday, open the dashboard, filter for quotes expiring this week, and Slack each rep whose quotes are at risk. Five minutes, prevents 100% of the problem going forward.
Recovering Expired Quotes
Still within 7 days? Go to Sales → Quotes → filter "Expired." Click "Reactivate Quote" and set a new expiration date. The quote returns to where it was.
Already cancelled (past 7 days)? Open the cancelled quote and click "Recreate." This creates a new draft with the same products, pricing, and structure. If the Salesforce opportunity is closed-won and the UI can't link to it, send Krishna the quote ID and opportunity ID and we'll connect them on our end.

Template Bundled with Above
What You're Running Into
When a quote-level discount is applied, the billing schedule section on the PDF still shows the original amounts (e.g., $108K instead of $100K). The discount applies at invoicing as a credit, so the schedule reflects standard charges. Customers do the math and get confused.
Two Paths Forward
Path 1 (template): We'll adjust the template to show post-discount billing amounts. This gets bundled with the cost disaggregation work above. Same timeline.
Path 2 (recommended for most Endor deals): For discounts that apply to a specific period (first year free, first 3 months free), use the schedule change ramp approach instead of the one-time discount product. Per-line discounts with schedule changes already show correctly in the billing schedule because they're applied directly to the line item, not as a separate credit. This eliminates the problem entirely for the majority of your deals.
Bottom line: Reserve the one-time discount product for true lump-sum contract credits where period doesn't matter. For period-specific promos, the ramp approach gives you a clean billing schedule out of the box.
