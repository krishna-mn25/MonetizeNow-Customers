2. One-Time Discount — Applied to first-year billing only›
Discounts #1 Priority Ready to Build
KKrishna · blueprint setupLLeidy · sandbox sign-off
What You're Running Into
Reps offer 2-3 months free (or a discounted first year) as an entrance incentive. There's no obvious way to set this up so the discount only applies to the first billing period and renewals come in clean. Reps are building quotes manually in Google Sheets and emailing PDFs. That breaks Salesforce data, makes auditing manual, and hides pipeline from Casey.
How We Solve It — Schedule Change Ramp
MonetizeNow supports Schedule Changes at any date within a contract (not just annual boundaries). We use this to build the promo structure directly on the real product:
  1. Add the actual subscription product to the quote (e.g., Endor Package Firewall). Not a promo version.
  2. Apply a 100% discount on that line item for the first period.
  3. Add a Schedule Change at the date the free period ends (month 4, end of Y1, etc.). Set discount to 0% on that segment.
  4. Result: Free period bills at $0, everything after bills at full price. One product, one line item, clean billing schedule.
Blueprints Make This Repeatable
We'll save this as a Quote Blueprint called "New Deal — 3 Months Free." Rep selects it, gets the full ramp pre-built, and only adjusts customer, quantities, and dates. Blueprints preserve the entire schedule change structure.
We'll also create a "Renewal — Full Price" blueprint for renewal quotes.
Renewal Behavior
For contracts with promo ramps, we set renewal type to Manual Renewal (contract renewal settings). When renewal time comes, Leidy or the rep creates the renewal using the "Full Price" blueprint. No promo pricing carries forward.
Sandbox first. We'll build both blueprints in sandbox and test the full lifecycle (quote → process → billing run → renewal). Krishna will have sandbox ready for review by Thursday.
Open question for Casey: During free months, ARR will show $0 for those periods since MonetizeNow calculates ARR from the billing amount. If you need ARR to show the full committed contract value regardless of the promo, we can build a custom TCV report. Should we discuss this in the Casey meeting?

4. Proration — Prorated value not displaying total correctly›
Pricing Sandbox Test Needed
KKrishna · test + recommendLLeidy / Casey · decide
What You're Running Into
On the OpenAI quote, 2,600 seats × $310 should be $806,000. MonetizeNow calculated ~$804,000 because it prorates to the exact day. A 7-month-5-day co-term period doesn't divide cleanly, so there's a ~$2K difference from what the customer expected.
The Option
MonetizeNow has a product-level setting that turns off day-level proration. When set to "Non-Prorated," the system charges the full period amount. 2,600 × $310 = $806,000 exactly.
  1. Go to Product Catalog → select the product
  2. Find Proration Policy
  3. Change from "Prorated" to "Non-Prorated"
Product-level, not per-quote. This applies to every quote using that product. If some deals need exact day-level proration and others need simple multiplication, this toggle won't cover both. We should test in sandbox with an amendment scenario (adding seats mid-term) to confirm the behavior.

5. SKU Pricing — Reps can mark up, but markdowns need approval›
Pricing Rules Ready to Configure
KKrishna · build ruleLLeidy · approve logic
What You're Running Into
Reps need to adjust unit prices upward (anchoring strategy), but enabling Account Specific Rates also lets them lower prices below list. You don't want that without RevOps approval. Right now only admins can make changes, making you the bottleneck.
Two-Step Setup
Step 1: Open up pricing permissions. In Quote Settings → Account Specific Rates, grant your sales reps the ability to adjust prices on quotes.
Step 2: Add the guardrail. We create an Approval Rule that fires when a rep sets a price below list. MonetizeNow tracks this as a positive discount percentage. So the rule condition is: discount percentage > 0% on an account-specific rate. Markups show as zero discount and go through without approval.
What this means for you: You only get approval notifications when a rep goes below list. Everything at or above list price just works. You're no longer the bottleneck for standard pricing.

6. No MSA for Renewals›
Terms Rules Ready to Configure
KKrishna · configureLLeidy · choose option
What You're Looking For
Renewal quotes shouldn't include the MSA since the customer already signed it on the original deal. Keeps the renewal document clean and focused on the order form only.
Option A — Conditional Term (Recommended)
MonetizeNow's Rules Engine exposes quote type (New, Renewal, Amendment) as a condition field for Conditional Terms. So we:
  1. Remove the MSA from the default Quote Documents section (Settings → Quote Settings → Quote Documents), so it doesn't auto-attach to every quote
  2. Create a new conditional term: "Master Service Agreement (New Deals Only)"
  3. Condition: quote type = New
  4. Renewals and amendments skip the MSA automatically. New deals get it every time.
Option B — Manual Attach (if all renewals go through a CSM)
If every renewal has a human reviewing before it goes out:
  1. Remove the MSA from default Quote Documents
  2. Reps manually attach the MSA from the quote-level document upload on new deals only
  3. Add a Validation Rule: if quote type = New AND no MSA document attached → block with "Please attach the MSA for new customer deals"
Option A is more reliable since it's fully automated. Option B works if your team is disciplined and every renewal has human review before sending.
Open question: Do all your renewals go through Leidy or a CSM before being sent, or do some auto-send? This determines which option is safer.

Primary Quote in SFDC — How to change it›
Lifecycle Salesforce Answered
Your Question
"I am unable to change the primary quote in SFDC. Is this function not available? Or does it just make the most recent quote the primary without the ability to change?"
How It Works
Primary quote is managed in MonetizeNow, not Salesforce. It syncs to SFDC but can't be changed from the SFDC side. To change it:
  1. Open the quote in MonetizeNow
  2. Click "Set as Primary" on the quote you want
  3. The change syncs to Salesforce automatically
The Auto-Assignment Rules
Becomes primary: First quote linked to an opp. Or when a quote is accepted/processed (all other non-finalized quotes auto-cancel). Or when manually set.
Stops being primary: When deleted or cancelled (system picks a replacement: highest stage, then newest). Or when another quote is manually set as primary.
For your reps: Multiple drafts are fine, they clean up automatically when one gets processed. If the primary looks wrong, just click "Set as Primary" on the correct quote in MonetizeNow.
Discount Scenario — Year 1 Quote-Level Credit1
Y1-Only Discount Shown as a Negative Line Item at Quote Level›
Discounts Feature Request Workaround Available
KKrishna · workaround setupEEng · feature request
What You're Looking For
On a 3-year contract, you want to apply a discount that only hits Year 1, and you want it to show as a separate negative line item at the bottom of the quote (like the existing One-Time Discount product does). Customer sees the full product pricing, then a clear "-$X Year 1 Discount" at the bottom. Clean, transparent, easy for their finance team to understand.
Why It Doesn't Work Today
The One-Time Discount product (the negative line item at the bottom) distributes its credit evenly across all billing periods. On a 3-year annual contract, a $30K OTF discount shows as $10K credit per year, not $30K in Year 1 only. There's no setting to front-load the credit to a specific period.
Feature Request (Logged)
We've logged this as a feature request: add an allocation strategy to the One-Time Discount product (options: "Even across all periods" vs. "Apply to first period only"). This would give you the exact visual and billing behavior you want. We'll share timeline when product prioritizes it.
Workaround A — Per-Line Schedule Change (Functional Match)
This achieves the exact same billing result (Y1 discounted, Y2-3 full price) using Schedule Changes:
  1. Apply the discount directly on each product line for Y1 (e.g., 20% off)
  2. Add a schedule change at Y2 start, set discount to 0%
  3. Y1 invoices reflect the discount, Y2-3 invoice at full price
Trade-off: The discount shows on each line item (e.g., each product shows "$X minus 20%"), not as a single negative line at the bottom. The math is identical. The visual is different. For most customer finance teams, per-line discounts are actually easier to reconcile than a separate credit line.
Workaround B — OTF Discount + Template Note (Visual Match)
If the visual presentation (single negative line at the bottom) matters more than period-specific allocation:
  1. Use the existing One-Time Discount product for the full discount amount
  2. Accept that it distributes evenly across all 3 years
  3. Add a Quote Item Note or template note clarifying: "Discount of $X applied, representing a Year 1 entrance incentive"
Trade-off: The visual is what you want (single line at bottom), but the billing distribution is even, not Y1-only. Y1 invoices don't get the full credit. This works if the customer cares about the total discount amount more than which invoice it hits.
Workaround C — Both Together (Best of Both)
Use the per-line schedule change (Workaround A) for the actual billing math, then request the template customization (item #3 above) to add a "Total Year 1 Discount: -$X" summary line at the bottom of the quote output. This gives you both the correct billing AND the visual presentation. The template change is already in the engineering queue.
Our recommendation: Workaround C. Per-line schedule change handles the billing correctly. The template customization (already needed for the cost disaggregation request) adds the visual summary line. This covers both needs without waiting for the feature request.

Quote Expiration and Recovery Process›
LifecycleReady to Share
LLeidy · weekly check
How Expiration Works
Quotes auto-expire 30 days after creation (configurable). Then a 7-day grace period to reactivate. After that, auto-cancel.
Prevention
The "MonetizeNow View for RevOps" dashboard is in your tenant under Reporting. Shows each rep's quotes, status, and expiration dates. Reps can extend expiration from the quote header. Recommended: Every Monday, 5 minutes, check for expiring quotes, Slack each rep.
Recovery
Within 7 days: Sales → Quotes → filter "Expired" → "Reactivate Quote." Past 7 days: Open the cancelled quote → "Recreate" (same products/pricing, new draft). If the SFDC opp is closed-won and can't relink from UI, send Krishna the quote + opp IDs.
