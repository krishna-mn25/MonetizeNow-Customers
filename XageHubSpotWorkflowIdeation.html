3. Workflow Decision Logic

Trigger

When: Deal property monetize_quote_status changes to PROCESSED This fires AFTER MN's final sync. Quote is locked. No further MN updates will occur. Safe to write.

Billing Frequency Mapping

MN = MONTHLY (1 month) → Set hs_recurring_billing_period = "monthly"
MN = QUARTERLY (3 months) → Set "quarterly"
MN = SEMI_ANNUALLY (6 months) → Set "semi_annually"
MN = ANNUALLY (12 months) → Set "annually"
MN = BIENNIALLY (24 months) → Set "per_two_years"
MN = TRIENNIALLY (36 months) → Set "per_three_years"
MN = CUSTOM (7, 4, 11, etc.) → No matching HS value. See 95/5% handling below.

Recurring / One-time Mapping

MN product_type = ADVANCE → Set as Recurring
MN product_type = ONE_TIME → Set as One-time
MN product_type = ARREARS / USAGE → TBD: How should usage products be classified?

Term Mapping

MN contractLength available → Set hs_term_in_months = MN contract length (e.g., 12)
Contract is partial month (11m 30d) → Round to nearest month (12)? Or leave exact? Need Xage input.

4. The 95% / 5% Split

95% — Standard billing frequencies

These map 1:1 to HubSpot values. Workflow handles them automatically. Monthly, quarterly, semi-annual, annual, bi-annual, tri-annual → direct match. No human intervention needed.

ARR accuracy for the 95%:

Deal typeMN AmountHS ARR after workflowMN ARRMatch?
Full-year annual (no proration) $4,712.77 $4,712.77 × (12/12) = $4,712.77 $4,712.77 ✓ Exact
Prorated annual (11m 30d) $4,700.10 $4,700.10 × (12/12) = $4,700.10 $4,712.77 Off by $12.67
Prorated deals: HS ARR will always differ from MN ARR by the proration gap. HS computes ARR = price × (12/period). MN's price is the prorated total. HS annualizes the prorated amount at 1:1 for annual billing, producing a lower ARR than MN's annualized calculation.

Workaround: For exact ARR in reports, use monetize_quoteitem_arr deal property. For HS-computed ARR, the gap is small and only affects prorated deals (typically net-new or mid-term amendments, not renewals).

Question for Xage: Is this gap acceptable? Most renewals are full-year (no gap). Net-new deals starting mid-period will have a small ARR gap. The monetize_ ARR property always has the exact number.

5% — Custom billing frequencies (7-month, 4-month, etc.)

HubSpot will not accept custom month values for billing frequency. The workflow cannot set "7-month" or "4-month." Options:

5. Sequence Protection: Closed Won → Processed

❌ What used to happen (the "undoing" problem)
  1. Heather manually corrects HS line item values
  2. Heather marks deal Closed Won in HS
  3. She expects nothing to change
  4. She processes quote in MN
  5. MN fires final sync → overwrites her corrections
  6. HS values back to "incorrect"
✓ How it works now with Option 2
  1. Heather does NOT manually correct HS values
  2. She marks deal Closed Won in HS
  3. She processes quote in MN
  4. MN fires final sync (qty=1, price=total, dates)
  5. monetize_quote_status = PROCESSED
  6. Workflow fires: sets billing freq, recurring/one-time, term
  7. HS recomputes ARR/MRR from updated fields
  8. Final state reached. No further updates.
The key change: Heather stops manually correcting HS values. The workflow does it after MN processing. MN sync and workflow never conflict because:
• MN owns: qty, price, dates (writes on every sync)
• Workflow owns: billing freq, recurring/one-time, term (writes only after PROCESSED)
• No field has two owners. No stepping on each other.

8. Separate Workstream: Reporting Transition (Option 2A/2B)
